# Работа с репозиторием

Инструкции запуска и сборки находятся в [руководстве разработчика](docs/development.md), карта кода — в [описании архитектуры](docs/architecture.md).

1. Создайте ветку от актуальной `main` для одной связанной задачи.
2. Установите зависимости через `npm ci`. Изменения зависимостей сохраняйте вместе с `package-lock.json`; изменения Rust-зависимостей — с `src-tauri/Cargo.lock`.
3. Внесите изменение и проверьте затронутые сценарии. Для исправления ошибки сохранения, импорта или преобразования текста добавьте регрессионный тест.
4. Выполните `npm run check` и `npm run test:e2e`. Для нативных изменений соберите соответствующую платформу.
5. Подготовьте небольшой осмысленный коммит и pull request с описанием поведения и результатов проверки.

Используйте UTF-8 и правила `.editorconfig`. Общая логика редактора находится в `src/`; нативные различия изолируются в адаптерах. Сохраняйте совместимость идентификаторов команд, старых пресетов и Data v2. Любой набор изменений текста должен сохранять ожидаемое поведение Undo/Redo.

В Git хранятся исходники, конфигурация, тесты и lock-файлы. Логи, локальные SDK/JDK, `node_modules`, сборки, пользовательские экспорты и ключи подписи не добавляются. Gradle wrapper, включая JAR, является частью исходного проекта и должен оставаться в репозитории.

CI собирает Windows NSIS и Android debug APK без установки приложения и без подключения устройств. Его артефакты предназначены для проверки сборки и не заменяют подписанный релиз.
