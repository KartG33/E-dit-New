# Отчёт о сборке и проверке Android APK

**Дата финальной проверки:** 6 августа 2026 года
**Проверяемая версия:** E-dit 2 `2.0.4` (`versionCode 20004`)
**Тип сборки:** debug APK

## 1. Итог

Мобильный этап 6 завершён. Debug APK приложения E-dit 2 был собран, установлен на Xiaomi Redmi Note 13 Pro и проверен в портретной и горизонтальной ориентации. Во время проверки были найдены и исправлены два связанных дефекта размещения интерфейса под системными областями Android: перекрытие верхней панели в портретной ориентации и перекрытие той же панели в landscape-компоновке.

Также были подключены финальные Android launcher/adaptive icons, проверены нативные Import/Export, экранная клавиатура, Android Back, восстановление текста после перезапуска, History, Presets и Suno Tags.

Результат был опубликован в PR [#5 — Finish Android APK verification](https://github.com/KartG33/E-dit-New/pull/5) и объединён в `main` merge-коммитом `aee72b138992eb43d83a3dec16e2a4849c96f941`.

### Подключение устройства

Windows видел телефон по USB как MTP-устройство, но USB ADB transport не появился. Был установлен официальный Google USB Driver в Android SDK, однако его INF не содержит Xiaomi VID, поэтому принудительная подмена драйвера не выполнялась. На телефоне уже была активна и спарена беспроводная отладка, поэтому использовалось безопасное подключение:

```text
adb connect 192.168.0.101:46179
adb -s 192.168.0.101:46179 ...
```

Это было операционным обходом проблемы USB-драйвера и не потребовало изменений кода приложения.

## 4. Сборка и автоматические проверки

### 4.1. Web-тесты

Финальный прогон выполнялся командой:

```text
npx vitest run --pool=threads --maxWorkers=1
```

Результат:

- 18 test files passed;
- 130 tests passed;
- ошибок нет.

Обычный параллельный запуск один раз превысил временные лимиты нескольких UI-тестов на Windows. Отдельный повтор проблемного `CommandPanel.test.tsx` в thread pool прошёл: 8 из 8 тестов. После этого весь набор был повторён одним worker и завершился успешно. Изменения тестовых таймаутов или самих тестов не потребовались.

```text
npm run lint
```

Результат: `oxlint` завершился без ошибок.

### 4.3. Production web build и Capacitor sync

```text
npm run android:sync
```

Команда выполнила:

- TypeScript build;
- production Vite build;
- копирование `dist` в Android assets;
- создание `capacitor.config.json`;
- синхронизацию Android-плагинов.

Результат: сборка и синхронизация завершились успешно. Были обнаружены плагины App, Filesystem, Keyboard и Share; SystemBars зарегистрирован непосредственно из `@capacitor/core`.

### 4.4. Gradle

```text
.\android\gradlew.bat -p android assembleDebug --no-daemon
```

Результат: `BUILD SUCCESSFUL`.

До APK-проверки также выполнялись Android unit test и `cargo check --locked --manifest-path src-tauri/Cargo.toml`. Они прошли успешно. Изменения этапа не затрагивали Rust/Tauri-конфигурацию.

## 8. Что проверено автоматическими тестами, а не изменением данных на телефоне

Чтобы не оставлять искусственные пользовательские данные:

- на финальном APK не сохранялся тестовый preset;
- на финальном APK не добавлялся тестовый Suno tag;
- в Import не выбирался файл и не выполнялась замена базы.

Создание, применение, изменение и удаление presets, операции Suno Tags и атомарный Data import покрыты существующими Vitest-тестами. На телефоне отдельно проверялись доступность соответствующих экранов, навигация, прокрутка, нативные окна и safe-area.

Desktop 1280 × 800 визуально не переснимался во время финального APK-прогона. Desktop-компоновка была проверена на предыдущем мобильном этапе; в текущем исправлении desktop получает safe-area fallback `0px`. Дополнительно прошли production build, линтер и web-тесты.
